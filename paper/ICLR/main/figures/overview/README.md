# Overview 右半边推理流程

`sc_pc_reasoning` 提供 draw.io、SVG、PDF、PNG，SC 在上，PC 在下。仅生成右半边，未拼接 token 矩阵，未替换论文或 method 图。

参考 `../ref/SC+PC.png` 的独立完整生成与跨窗口前缀复用关系，沿用 NOVA 参考图系的白底、蓝色、紫色及浅灰色。蓝色仅表示生成过程，不表示不同路径的 token 相同；紫色表示共享前缀。没有实验数字、正确性标记或重复片段编码。

PC 展示初始采样、Answer agreement、Prefix selection、共享前缀、Trial and recovery 与最终投票，与 method 图的技术名词对应。初始有效答案仍参与最终投票。省略门控公式、评分、试用和回退的内部条件及多轮前缀更新，这些细节保留在 method 图和正文。

统一的 22 × 22 方形表示抽象推理步骤，26 × 26 圆形表示答案，与 method 图的形状语义对应。圆形蓝色在本图仅表示答案角色，不声明答案相同或正确。步骤数量、间距及分支数量是示意，不表示 token 数或实测节省率。没有对重复片段进行编码。2026-09-20 根据作者反馈，将原先的简单条形改为逐步推理链和圆形答案，并补充三个方法阶段名称。

## 当前版本（参考 A/B 模块重绘）

当前采用浅蓝色 SC 背景和浅紫色 PC 背景，背景无外框。除推理方格、答案圆形及背景外，功能模块均有黑色边框。纵向间距压缩 14%，画布从 900 × 1380 调整为 900 × 1187；推理方格和答案圆形保持原尺寸，不随间距压缩变形。

从仓库根目录运行 `python3 paper/ICLR/figures/overview/build_reference_overview.py` 重新生成当前版本。旧的 `build_overview.py` 保留上一版设计，不应运行以覆盖当前交付图。

当前 SC 采用问题栏和逐行独立轨迹，PC 采用三个纵向递进窗口与窗口间的 Prefix selection 横条，更直接对应参考图 A/B 的表现形式。圆形答案用蓝色、黄色区分类别，不表示正确或错误，也不是实际观测比例；推理方格不编码重复片段。所有推理方格为 22 × 22，所有答案圆形直径为 24。PC 图中的紫色方格表示继承的前缀，不是重新生成。省略具体阈值、评分公式、两击重置及其他边界分支。

虚线 recovery 路径表示窗口 2 已通过并提交较短前缀后，窗口 3 的较长前缀试用失败，返回已提交的较短前缀。不是返回失败的提议，也不是所有失败都回到根。仍保留所有有效答案参与最终投票的说明。

复用 method 的场景渲染器，不修改 method 产物。draw.io 为原生可编辑形状，SVG 字形使用矢量轮廓以保持渲染一致性。
